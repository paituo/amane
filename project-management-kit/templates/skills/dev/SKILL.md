# 开发流程

本 skill 只描述流程规范, 不涉及项目具体内容.

## 流程

以 Issue 为例:

1. **获取内容**: 用 `gh issue view <编号> --comments` 读取正文与全部评论.
   `status:triaged` 表示维护者已确认; 未带该标签时不得开始实现, 把判断报告给用户.
2. **评估**: 简要评估可行性、必要性、预计工作量, 给出「要不要做」的判断.
3. **方案准备**: 复杂任务先写方案并让第二个 Agent 评审; 经用户确认后进入实现.
   任务足够简单、用户要求直接执行、或用户已给出确定方案时, 可直接执行.
4. **实现**: 除简单任务和非代码任务 (文档修改、样式调整、typo) 外, 所有变更在独立 worktree 中进行.
   过程中及时提交, 但不创建 PR.
5. **文案自查**: 按 `<DOCS_DIR>/writing.md` 与 `terms.md` 检查开发文档、注释、提交说明.
6. **测试自查**: 按 `<DOCS_DIR>/testing.md` 检查用例分层、边界与非法输入、是否存在玩具测试.
   变更规模较大时, 第 5、6 步交给 subagent 独立进行.
7. **用户验收**: 如有必要, 准备验证数据, 然后启动本地服务供用户复核.
8. **起草 PR**: 用户批准后推送; 后续按 `pr` skill 处理.

**严禁未经批准执行远程操作**: 推送分支、创建或更新 PR、回复或关闭 Issue.

## 验收

**何时需要验收**:

- 前端样式变更;
- 用户可见的行为变更;
- 难以通过测试验证的改动.

其他情况不需要验收. 例如修复解析器, 测试已经能验证正确性, 不必验收.

目标是用户打开页面即可验证, 不需要自己插入数据或修改配置:

- **数据**: 界面所需对象由你准备; 涉及迁移且空库无法满足时, 可复制开发环境的库.
- **配置**: 功能需要配置项才能生效时, 把该项置为生效态.
- **临时代码**: 仅当真实数据无法构造所需状态时使用; 不提交, PR 合并后一并移除.

数据准备完成后直接启动服务, 不再询问用户.
